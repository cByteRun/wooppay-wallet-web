## Устройство приложения

Весь прикладной код размещён в `app/_features/` по слоям FSD. Префикс `_` делает папку приватной для App Router: она не создаёт URL и не конфликтует с существующим `/features`. Документация доменов остаётся в `docs/features/`.

```text
app/
  layout.tsx                 # общий layout, metadata и правовое уведомление
  page.tsx                   # тонкий вход главной
  faq/page.tsx               # тонкий вход FAQ
  faq/[slug]/page.tsx         # вход деталки, dynamicParams = false
  features/page.tsx           # прежний публичный /features
  ...                        # остальные прежние маршруты
  robots.ts, sitemap.ts, opengraph-image.tsx
  _features/
    pages/                   # home, faq, faq-guide, service и остальные экраны
    widgets/                 # site-nav, official-help
    features/                # app-download, support-assistant
    entities/wallet/model/   # content.ts, schema.ts
    shared/                  # config, lib/seo, ui
```

- `@/` указывает на `app/_features/`. Импорты идут непосредственно к нужным модулям; старые совместимые входы `components/` удалены.
- Направление зависимостей: маршруты → pages → widgets → features → entities → shared. Слой может обращаться к любому нижележащему слою; нижележащие слои не импортируют страницы или маршруты. `pages/service` содержит общий экран сервисных страниц, а не глобальный UI-компонент.
- `entities/wallet/model/content.ts`: единые факты для FAQ, детальных страниц и metadata.
- `shared/config/site.ts`: прежний реестр URL, домен, магазины, политика индексации. `shared/lib/seo/metadata.ts` и `shared/ui/structured-data.tsx`: canonical, OG/Twitter и безопасный JSON-LD.
- `features/app-download`: серверные ссылки/QR и небольшое клиентское улучшение выбора платформы. Перенос не добавляет `use client` к страницам и виджетам.
- Маршруты реэкспортируют экран и metadata из `pages`. Конфигурация маршрута `dynamicParams = false` остаётся буквальным значением в файле App Router для статического анализа Next.js.
- URL, canonical, H1, JSON-LD, sitemap, robots и OG endpoint сохранены. Внутренние пути файлов не используются как публичные URL. Скрипт `check:seo` читает готовый HTML всех 14 страниц и использует новый путь к модели выбора платформы.

## Рендеринг и обновления

SSG для публичных страниц; для известных FAQ — `generateStaticParams`, неизвестный slug — 404. Клиентская аналитика и интерактивность добавляются поверх HTML. B2B-страница также может быть статической: наличие формы не требует SSR. Приём формы — отдельный серверный обработчик с валидацией, rate limit и надёжной доставкой.

После подключения CMS: предпросмотр с авторизацией и noindex; публикация утверждённой версии → подписанный webhook → инвалидация кеша страниц, sitemap и связанных данных. SLA ≤5 минут по ТЗ. Не полагаться только на длительный ISR для изменившихся тарифов. Ошибка CMS не должна публиковать нулевую комиссию или черновик; сохранять последнюю утверждённую версию, сигнализировать редактору.

RU пока без префикса. При вводе локалей — `/ru`, `/kk`, `/en`, постоянные редиректы старых RU URL, self-canonical и взаимные hreflang только опубликованных переводов. Код казахского языка — `kk`, а не `kz`. Route groups сами не создают SEO-сущностей и не меняют URL.

## Границы и решения

Публичные финансовые факты подтверждает заказчик. ТОО Segmento — заказчик проекта; это само по себе не подтверждает статус оператора кошелька. Не публикуем выдуманные лицензии, PCI DSS, комиссии, скорости зачисления, рейтинги и перечни игровых сервисов.

Техническая готовность к индексации не гарантирует включения в индекс, топа или цитаты. Google сообщает, что специальные AI-файлы и schema для AI-поиска не требуются: [официальное руководство](https://developers.google.com/search/docs/appearance/ai-features). `llms.txt` не включён в критический путь; при подтверждённом потребителе генерировать из тех же фактов, без отдельной ручной копии.

SEO/GEO, ASO магазинов и платная реклама — отдельные каналы. SEO готовит посадочную страницу; ASO требует доступа к App Store Connect / Play Console и работы над карточкой, скриншотами и конверсией. Реклама требует кампании, бюджета и проверки применимости к финансовому продукту. Наличие schema не запускает рекламу. По [OpenAI Docs](https://developers.openai.com/api/docs/bots): OAI-SearchBot обслуживает поиск, GPTBot — возможное обучение, OAI-AdsBot проверяет страницы, поданные как реклама. Разрешения ботов и WAF проверяются независимо; текущий wildcard разрешает публичный контент.

## Разногласия требований

- Поддержка: мини-ТЗ/Business Vision −20%, полное ТЗ −15%. Для планирования используем −20%, договорной критерий требует согласования.
- 10 000 визитов ×15% =1 500 сессий с переходом; 2 000 установок из полного ТЗ не следуют из этой воронки. Установки измерять отдельно; не объявлять KPI достигнутым по событиям клика.
- Мини-ТЗ говорит об органических визитах, полное ТЗ — о визитах. В growth-плане используем более конкретный organic search и отдельно считаем весь трафик.
- Требование «все URL индексируются» проверяется после запуска; до запуска приёмка подтверждает доступность и пригодность к индексации, решение поисковика не контролируется разработчиком.

## Приёмка и эксплуатация

Код: lint, typecheck, production build, `check:seo` для preview и production. Проверка готового HTML: уникальные metadata, canonical, H1, JSON-LD, рабочие внутренние ссылки и QR, sitemap, noindex preview. Это не проверка живого CDN.

Запуск: согласованный домен, редактура, аналитический адаптер и согласие, Search Console / Яндекс Вебмастер / Bing, HTTP 200/404/301, WAF без CAPTCHA для нужных краулеров, мобильный аудит. `SITE_INDEXING_ENABLED=true` задаётся при production-сборке; noindex не является защитой приватного stage — для него нужен контроль доступа.

NFR из ТЗ: LCP ≤2,5 с на мобильном 4G, Lighthouse ≥85, главная ≤1 МБ, WCAG AA, uptime ≥99,5%, 1 000 одновременных пользователей без ухудшения LCP более 30%. Дополнительные полевые цели p75: INP ≤200 мс, CLS ≤0,1. Измерять на опубликованном окружении; локальная сборка не доказывает эти показатели. CMS: backup ежедневно, retention 30 дней, RTO ≤4 ч, RPO ≤24 ч; заявки хранятся до подтверждения доставки, цель ≤1 минуты.
