# Roadmap Wooppay Wallet Web

Основание: [мини-ТЗ](docs/TZ/mini_TZ.md), [ТЗ](docs/TZ/TZ.md), [Business Vision](docs/business-vision.md). [Архитектура и расхождения KPI](docs/architecture.md). Отметка означает реализованный результат в репозитории; запуск и экономический эффект принимаются отдельно.

## Фаза 1 — MVP: официальный источник и путь в приложение

### M1 — Поиск и доверие · [feature](docs/features/seo-discovery.md)

- [x] FR: серверный контент, metadata, canonical, sitemap, OG/Twitter, JSON-LD.
- [x] FR: три адресуемых FAQ, внутренние ссылки, общий источник фактов.
- [x] NFR: noindex preview, контент и ссылки без JS, статические страницы.
- [ ] DoD запуска: домен, утверждённый контент, GSC/Вебмастер/Bing, публичный HTTP/WAF и CWV-аудит.

### M2 — Привлечение в приложение · [feature](docs/features/app-acquisition.md)

- [x] FR: App Store / Google Play, QR, /download и выбор платформы.
- [x] NFR: рабочий переход без JS и метрик.
- [ ] DoD: мобильная приёмка, измеряемая конверсия сессии в переход, атрибуция установок совместно с M6.

### M3 — Самообслуживание · [feature](docs/features/self-service.md)

- [x] FR: FAQ-хаб и адресуемые ответы об установке, условиях, поддержке.
- [ ] FR: утверждённые инструкции оплаты/игр, причины отказов, поиск с пустым состоянием и эскалацией.
- [ ] NFR: редакционная актуальность, проверка доступности.
- [ ] DoD: сравнение доли типовых обращений с baseline; цель −20%, расхождение −15% согласовано.

### M4 — Партнёры · [feature](docs/features/partner-hub.md)

- [ ] FR: /partners, проверенные реквизиты, форма и надёжная доставка CRM/email.
- [ ] NFR: согласие, антиспам, сохранение и повторы, доставка ≤1 минуты.
- [ ] DoD: сквозной тест доставки/сбоя/дубля; отчёт валидных заявок, цель ≥5/месяц.

### M5 — Управление достоверностью · [feature](docs/features/content-governance.md)

- [ ] FR: CMS, workflow, роли, preview, версии, тарифы и лимиты.
- [ ] NFR: публикация ≤5 минут, backup и восстановление, защита админки.
- [ ] DoD: редактор публикует без разработчика, юридическая проверка, обучение 2×2 часа.

### M6 — Измерение роста · [feature](docs/features/measurement.md)

- [x] FR: локальное событие клика store/placement/path.
- [ ] FR: GA/Amplitude, consent, события поддержки/статей/поиска/форм, атрибуция магазинов.
- [ ] NFR: метрики не задерживают CTA; нет персональных текстов в аналитике.
- [ ] DoD: тестовые события в провайдере, сессионная дедупликация, dashboard и baseline.

### M7 — Локализация и доверие · [feature](docs/features/localization-trust.md)

- [ ] FR: редакторские KK/EN, переключение, hreflang, редиректы, юридические страницы, контакты и вакансии.
- [ ] NFR: WCAG AA и профессиональная редактура.
- [ ] DoD: переводы доступны и взаимно связаны; опубликованные сведения подтверждены.

Общий DoD MVP по полному ТЗ требует завершения всех семи milestones: текущая техническая SEO-основа не означает готовность всего сайта. Порядок зависимостей: M1/M2 → M3; M5 обеспечивает актуальность M1/M3/M7; M6 нужен для оценки всех экономических KPI. M4 развивается параллельно в календарном плане.

## Фаза 2 — Рост: 1–6 месяцев после запуска

- [ ] День 28: индексирование, ошибки и брендовые запросы; убрать технические барьеры.
- [ ] День 90: контент по подтверждённому спросу, первые 3 приоритетных запроса, ASO карточек.
- [ ] Месяц 6: 10 000 organic сессий/месяц, 15% с кликом (1 500), установки отдельно, ≥5 B2B заявок, эффект FAQ.
- [ ] Ежемесячно: фиксированный мониторинг AI-упоминаний, цитат и правильности ответов.
- [ ] При отдельном бюджете: Ads-эксперимент с проверкой доступности и политик, атрибуцией и пределом CAC.

## Фаза 3 — Развитие 2027–2030

- [ ] Ежеквартально пересматривать требования поисковиков и ИИ-платформ по официальным источникам.
- [ ] Добавлять новые форматы выдачи/агентные интерфейсы по данным спроса и логов, с измеримым эффектом.
- [ ] Масштабировать успешные кластеры и локали; оценивать прибыль и стоимость поддержки, а не только посещения.

Будущие алгоритмы, доминирование в выдаче и рекламный доступ не принимаются как известные факты.
